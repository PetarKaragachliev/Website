# Bulgarian Interface

The current analyzer, workout generator and shared seven-day nutrition table are Bulgarian-only, per the owner's explicit language choice. The original visual layout is restored without restoring English. The previous English/Bulgarian selector and static DOM-translation machinery were removed; old language preferences do not change the interface. Scientific names, LiftFuel branding, the requested Skinny Fat term, and original external sources retain their names.

Static HTML and body-model results use Bulgarian directly. `i18n.js`, `bg-models.js` and `bg-app.js` provide local translations for the existing language-independent nutrition model and its templates. No translation service or profile upload is used. Number display uses `bg-BG`; input parsing accepts decimal commas or dots without changing internal precision. RFM displays exactly one decimal place.

The application no longer writes `liftfuel.language`. Explicit data deletion still cleans up that old app-owned key without deleting unrelated browser data or masking a failure to remove a retained profile. Profile v6 and v1-v5 decoding are described in BODY_ASSESSMENT.md; legacy activity must be cleared in the UI and explicitly reselected as activity outside planned training.

Common age, weight, goal and outside-training activity are entered only on nutrition; training shows shared context and collects only its six settings. Bulgarian labels distinguish base/rest intake, training-day intake and estimated extra energy, never measured burn. Daily kcal round to nearest 10, grams to whole numbers, with unchanged internal precision. Explain unavailable energy/support limits without implying exercise is forbidden; no invented pace when all options are blocked. Sources/method: [TRAINING_ENERGY_POLICY.md](TRAINING_ENERGY_POLICY.md).

The former language-switch browser scenarios were replaced because that UI feature was explicitly retired, not skipped to conceal failures. Current checks include `tests/e2e/integration.spec.js` for automatic daily-table handoff, session snapshots/drafts, opt-in inputs only, fresh eligibility, legacy activity reselection, stale credits and cross-tab revocation. No health data belongs in URLs or persisted results. The original nutrient formula and reference tests remain. No screenshots, video or traces may be generated.
